# Диагностика: как найти причину проблемы

## Журнал приложения

Эфир пишет журнал: запуск (версия, система), сетевые адреса, поиск и найденные устройства, сопряжение, подключения и их
отказы с причиной, настройка соединения по шагам, разрешения Android, фоновый сервис, необработанные ошибки со стеком.

В журнале **нет** ключей доступа, токенов, содержимого файлов, буфера обмена, SMS и уведомлений.

| Где | Файл |
| --- | --- |
| Windows | `%USERPROFILE%\.efir\logs\efir.log`, предыдущий — `efir.1.log` |
| Android | внутренняя папка приложения, `logs/efir.log` (снаружи не видна) |

Проще всего взять журнал из приложения: **Настройки → Журнал**. Там последние 300 строк и кнопки: обновить,
копировать целиком, сохранить в файл или отправить (на ПК — файл в `Downloads\Efir`, на телефоне — системное
«Поделиться»), очистить.

Файл не растёт без конца: дойдя до 512 КБ, он становится `efir.1.log`, запись начинается заново.

## Что присылать

1. Что делали и что увидели (скриншот).
2. Журнал **с обоих устройств**: проблема соединения почти всегда видна только на одном из них.
3. Версию — она в первой строке запуска (`app: start 0.2.1, …`).

## Как читать

Строка: время, уровень (`INFO`, `WARN`, `ERROR`, `FATAL`), раздел и текст.

| Раздел | О чём |
| --- | --- |
| `app` | запуск, выход, второй запуск, необработанная ошибка |
| `net` | адреса устройства, ожидание подключений, поиск, найденные устройства |
| `pair` | ожидание с ключом, исход сопряжения и причина отказа |
| `link` | подключение, отказ и его причина, шаги настройки соединения, закрытие |
| `perm` | какие разрешения запрошены и что ответил человек (Android) |
| `service` | фоновый сервис Android |
| `screen` | показ экрана: начало и размер кадра, отказ и его код, остановка и кем |
| `media` | камера и звук: отказ другой стороны |
| `settings` | выбор папки в «Настройках» (без пути) |

Коды причин, по которым показ экрана не начался или закончился (в строках раздела `screen`):

| Код | Что значит |
| --- | --- |
| `screen_permission_needed` | на телефоне не ответили на вопрос Android о показе экрана за 45 секунд (или окно приложения закрыто) |
| `screen_refused` | на телефоне нажали «Отмена» |
| `screen_disabled` | на компьютере выключено «Показывать экран этого компьютера» |
| `screen_unavailable` | у устройства нет экрана для захвата |
| `screen_stopped` | показ остановили на показывающем устройстве (кнопкой или в системе) |
| `screen_no_answer` | показывающее устройство не ответило за минуту |
| `screen_failed` | сбой захвата; причина — строкой выше в журнале показывающего устройства |

## Известные причины

| Что видно | Причина | Что делать |
| --- | --- | --- |
| Android: окно «Ограниченные настройки» при включении службы ввода или доступа к уведомлениям | приложение установлено из файла, Android 13+ блокирует такие настройки | Настройки → Разрешения → «Выдать»: памятка по шагам. Коротко: попробовать включить, затем Сведения о приложении → ⋮ → «Разрешить ограниченные настройки» |
| «Неожиданный ответ сопряжения» (до 0.2.1) | телефон без разрешений на звонки и SMS падал при настройке соединения прямо внутри сопряжения | исправлено в 0.2.1: шаг пишется в журнал как `setup step "…" failed`, соединение остаётся |
| Компьютер не находит телефон поиском, хотя по адресу подключается (до 0.4.1) | поиск шёл только широковещательным пакетом, а Android отбрасывает такие пакеты по Wi-Fi без `MulticastLock`; телефон появлялся, лишь когда поиск открывали на нём самом | исправлено в 0.4.1: адресный опрос подсети и знакомых устройств; свёрнутый телефон появляется в пределах 15 с |
| «Найти устройство» не показывает телефон, хотя на вкладке «Рядом» он есть (до 0.4.2) | окно скрывало уже сопряжённые устройства | исправлено в 0.4.2: сопряжённое показано с пометкой и подключается нажатием |
| Порт 47812 занят или закрыт | другая программа, правило сети | «Настройки» → «Сеть» → «Порт соединения», затем перезапуск; в журнале `net: waiting for connections on port …` |
| Устройства не видят друг друга | разные сети, гостевой Wi-Fi с изоляцией клиентов, брандмауэр (входящие TCP 47812, UDP 47813) | «Проверить сеть»; подключиться по адресу вручную |
| «Ожидание первого кадра…» без конца (до 0.4.0) | Windows не умела показывать свой экран; телефон без заранее выданного разрешения отвечал ошибкой, которую смотрящая сторона не показывала; на Android 14+ захват падал без `MediaProjection.Callback` | исправлено в 0.4.0: Windows показывает экран, телефон сам спрашивает разрешение, причина отказа пишется под кнопкой и в журнал (`screen: …`) |
| Показ экрана телефона не начинается, код `screen_permission_needed` | окно Android о показе экрана не появилось или его не заметили: Эфир на телефоне свёрнут, а уведомления приложению запрещены | открыть Эфир на телефоне и повторить; выдать «Уведомления приложения» в «Настройках» → «Разрешения» |
| Нажатия по картинке экрана компьютера не действуют, окно «Управление недоступно» | на компьютере выключено управление (так по умолчанию) | на компьютере: «Настройки» → «Показ экрана» → «Разрешать управление этим компьютером» |
| Синхронизация или скачивание: «Путь вне разрешённых корней» | папка на другом диске компьютера не открыта другому устройству (до 0.4.0 её нельзя было открыть вовсе) | на этом компьютере: «Настройки» → «Папки» → «Добавить папку»; папка загрузок и папка правила на своём устройстве открываются сами |
| Windows: второй запуск ничего не показывает | первый экземпляр завис и держит замок | завершить `Efir.exe` в Диспетчере задач; строка `a second start` в журнале |
| Windows: падение до окна | — | `%USERPROFILE%\.efir\crash.log` и конец `efir.log` |
